我需要你为一个已经上线运行的 Web 产品做一次完整的 UI 重设计。请先理解产品和约束，再给设计方案。

## 产品是什么

**DD直连（ddzhilian）** —— 一个打开浏览器就能用的跨设备传输与协作工作台。不需要安装、不需要注册即可使用。

核心场景是：同一个网络里的手机、电脑、平板之间，快速互传文件和文本。技术上走 WebRTC 数据通道点对点直传，连不通时回落到服务器中转。在这个基础上叠加了聊天、AI 助手、生图和命令沙箱。

用户界面**全中文**。用户既有桌面端也有移动端浏览器，两端都是主要场景，不是「桌面优先移动兼容」。

## 现在长什么样，以及为什么要重做

现有界面刻意模仿微信 Windows 客户端：浅灰底（#f5f5f5）、72px 图标栏 + 280px 会话列表 + 自适应聊天区的三栏结构、#95ec69 的发送气泡绿、克制的动效。

这个方向能用，但有三个问题：

1. **它是一件仿制品，没有自己的识别度。** 用户第一眼会觉得「这是个微信的山寨版」，而不是记住这个产品本身。
2. **它借来的是聊天软件的信息架构，但这个产品的重心不是聊天，是传输。** 传输有自己的生命周期、进度、失败与重试语义，塞进聊天气泡里表达得很勉强。
3. **样式层已经失控。** 主样式表累积到 24000 多行，同时存在四套互相重叠的 CSS 变量前缀（`--cc-*` 来自微信仿制规范、`--dd-*`、`--snap-*`、`--ai-*`），共 112 个自定义属性。

所以我要的不是在现有基础上微调，是**重新确立视觉语言和信息架构**。

## 需要设计的界面

### 主工作台（最重要）

一个持续在线的工作区，同时承载会话和传输。桌面端目前是三栏，移动端是底部四标签。

- **导航层**：桌面是左侧窄图标栏；移动是底部四个标签 —— 消息、设备、传输、我的
- **会话列表**：公共房间、私有房间、设备直连会话、AI 助手，都在一个列表里。每行要能表达：头像/标识、标题、最后一条内容预览、时间、在线人数、未读数、置顶态
- **消息流**：三种条目类型混排 —— 文本、文件、系统通知。需要区分「我发的」和「对方发的」，需要支持引用回复、撤回（带消失动画）
- **输入区**：文本输入 + emoji + 「＋」菜单（文件、图片、拍照、OCR、AI、命令等工具入口）
- **传输队列**：桌面端是可折叠的侧边面板，移动端是独立标签页

### 传输状态（这是产品的核心，请重点设计）

一个传输任务有 8 个状态，每一个都要在界面上可读：

`排队中 → 等待对方上线 → 连接中 → 就绪 → 传输中 → 已完成 / 失败 / 已取消`

传输中要显示进度、速度、剩余时间、文件大小。失败要能重试，进行中要能取消。同时可能有多个任务并行。

请特别注意：**当前设计把这些状态塞进聊天气泡里表达，很拥挤也不好扫读。** 传输任务既要在消息流里有存在感（它是对话的一部分），又要能在专门的传输页里被完整管理。这个双重身份怎么处理，是这次设计最需要你想清楚的问题。

### 关键弹层与流程

- **接收文件确认**：对方发来文件时的接受/拒绝对话框
- **信任设备**：首次与某设备互传前的确认框，含短码校验和「记住此设备」
- **图片预览**：全屏查看，支持缩放
- **文档预览**：支持 PDF、Word、Excel、PPT、Markdown
- **OCR 面板**：在浏览器本地识别图片文字，出结果后可插入输入框
- **命令面板**：快捷操作检索

### 工具页面

这几个是从主工作台切换进去的独立视图：

- **AI 助手对话**：流式输出、模型选择器、额度显示、可上传图片、可联网搜索
- **图片生成**：提示词输入、生成历史、每日免费额度 + 付费余额
- **命令沙箱**：终端界面，运行代码并回显结果
- **设置 / 我的**：设备名、发现设置、主题、历史记录管理

### 营销页面（次要）

关于、隐私政策、服务条款、广告说明、联系我们。这五个页面主要用于广告审核合规，需要与产品视觉一致但可以简单。

## 硬性约束

这些不能改，请在设计里遵守：

- **技术栈**：React 19 + Next.js 静态导出、Tailwind v4。设计要能用 CSS 实现，不依赖运行时重排
- **浏览器**：Chrome/Edge/Firefox ≥ 91，Safari ≥ 15
- **深浅色双主题**：已有 `data-theme-mode="dark"` 机制，两套都要设计
- **用户可自定义气泡颜色**：用户能分别设置「我方」「对方」「AI」三种气泡的颜色，文字颜色按对比度自动计算。所以配色方案不能假设气泡颜色固定
- **中文排版**：正文以中文为主，混排英文、数字、代码。字体栈需要考虑 PingFang SC / Microsoft YaHei / Noto Sans SC 的回退
- **无障碍**：点击热区不小于 36px，需要可见的焦点态，对比度达标
- **动效克制**：这是长时间使用的工具，不是展示型页面

### 1. 设计方向（先给这个）

请给出 **2–3 个不同的视觉方向**，每个用一段话说清楚它的性格、它适合这个产品的理由、以及它和现在这版微信风格的区别。不要只是换配色 —— 我要的是不同的思路。

给完方向后**先停下来等我选**，不要直接展开。

### 2. 设计语言（选定方向后）

- 完整的色彩系统：中性色阶、主色、语义色（成功/警告/失败/链接），深浅两套
- 字体层级：字号、字重、行高、用途，覆盖中文排版
- 间距系统、圆角、层次（阴影或分割线的使用规则）
- **一套干净的 CSS 自定义属性命名规范**，用来取代现在那四套重叠的前缀

### 3. 关键界面设计

按重要性排序：主工作台（桌面 + 移动）→ 传输状态的各种形态 → 消息流的三种条目类型 → 输入区 → 关键弹层。

用 HTML + CSS 做成可以直接在浏览器里看的静态原型，不要只给文字描述。深浅两色都要能看到。

### 4. 组件规格

对每个核心组件给出状态清单（默认、悬停、按下、聚焦、禁用、加载、空、错误），以及具体数值。

## 一些具体的判断请你替我做

- 传输任务到底应该是消息流里的一等公民，还是应该有独立的呈现层？
- 桌面端三栏是不是最优解？还是说这个产品适合别的结构？
- 移动端四个标签（消息/设备/传输/我的）划分合理吗？
- 「设备」这个概念要不要在界面上弱化 —— 用户真正关心的是「把东西传给谁」，而不是「有哪些设备在线」？

这些我没有预设答案，你觉得应该改就改，但请说明理由。

## 最后

请不要给我一份安全的、模板化的、看起来像任何一个 SaaS 后台的设计。这个产品有很具体的性格：**它是临时的、快速的、不留痕迹的** —— 打开就用，传完就走，历史内容 24 小时自动清理。这个「轻」和「暂时」的特质，应该能在视觉上被感觉到。
